# 已保存 API 复用与切换模型（2026-10-23）

## 修复的问题

上一版模型页只支持新输入的密钥读取模型列表，即使配置已经保存，也会要求再次填写。现在打开页面会读取本机已保存的兼容 API 配置，默认选择当前模型所属的 API，自动获取列表；点击「测试并切换模型」才进行生成测试、保存和运行时重连。

界面不回填密钥，只接收连接 ID、显示名称、版本指纹和当前模型。读取/切换请求通过连接 ID 由控制器同时解析已保存的密钥及地址，不允许请求方为该密钥指定另一个地址。测试期间配置已变化时拒绝覆盖。失败不替换原模型；已知模型能力参数、供应商元数据及原模型列表保留。

当前模型即使没有出现在服务商最新列表中，也保留「当前模型」选项。接口不提供列表时，可使用已保存密钥搭配手动模型 ID。需要更换密钥时进入「更换密钥或配置其他 API」，也可返回已保存连接。

复用范围：已启用、使用普通字符串 API Key、OpenAI Chat Completions 协议且无额外请求头的供应商配置。其他协议、OAuth、SecretRef、自定义请求头的配置仍通过高级管理处理。

## 切换与上下文

切换不是新开对话。保存时仅更新模型配置及默认模型/机器人模型字段，机器人 ID、渠道绑定和预设保留。微信会话路由由账号、渠道、联系人决定，不包含模型 ID。正常切换没有调用 `sessions.reset`；后台重启清理的是遗留 `.lock` 文件，不是历史会话文件。打包运行时对模型变化记录新的模型快照并适配历史消息格式，不以模型变化为由清空历史。

已有历史仍受上下文容量、压缩、协议适配等限制，不能保证新模型获得所有原始消息或保持同样表现。显式「新开对话」与模型切换是不同操作。默认大肥鱼预设和联系人记忆文件也不因切换模型而清空。

当前保存模型后仍会重启后台，正在生成/发送的回复可能中断。界面提示等当前回复结束再切换，不能宣称无缝切换。没有在用户真实会话中强制切换或中断回复来验证此行为。
