# 第一轮功能精简

日期：2026-10-20。本轮目标是删除明确不属于微信接入助手的功能，保留自带 API 和微信链路，尚未开发完整首次配置向导。

## 已删除

- nexu 云账号登录、云端配置切换、官方云模型库存和周期刷新。
- 积分、奖励、签到、推广素材、GitHub 拉星入口和余额不足弹窗。
- Slack、Discord、飞书、Telegram、WhatsApp、钉钉、QQ、企业微信的连接页面与连接接口。
- 技能目录、技能安装与导入、安装队列、捆绑办公/图像/视频技能及外部办公集成。
- 独立聊天页面及其导航；仍保留会话存储和管理底层，供后续“新开对话 / 清理记录”使用。
- 前端和桌面统计初始化、控制器统计任务、聊天内容跟踪插件、飞书专用失败消息补发。

## 保留与限制

- 保留自带 API 的供应商编辑、模型选择、自定义兼容接口，以及原有供应商 OAuth 适配。这里的供应商授权不同于已删除的 nexu 云账号。
- 保留微信二维码、授权保存、账号索引与连接同步，以及内部 `nexu-runtime-model` 插件；它用于将选择的模型传入运行时，不是 nexu 云服务。
- 界面目前为“微信连接”“API 与模型”，基础语言设置仍可用。模型测试仍沿用上游实现，尚未升级为真实生成测试。
- 编译配置仅输出微信渠道及必要插件。旧云模型和其他 IM 配置不能进入运行配置；已有用户文件不做批量删除。
- 运行配置禁用所有模型工具调用、命令执行、网络搜索、自动任务、自动记忆写入与检索、心跳任务、原生命令和诊断上报。配置级回归已覆盖，真实运行时权限验收仍未完成。
- 上游自动更新管理器、周期检查和发布目标已停用，尚无自己的更新服务。
- 内部包名、部分底层兼容类型和上游参考文档仍保留。OpenClaw 依赖包自身携带的能力尚未进行裁剪，不承诺最终安装包体积。

## 验证方法

使用 Windows、Node.js 24.18.0、pnpm 10.26.0。依赖安装时跳过了项目自动准备完整运行时的脚本，Electron 开发二进制单独安装。

- 修改前的类型检查与 lint 均通过。
- 运行根目录 `pnpm typecheck`、`pnpm lint`、`pnpm test`。
- 单独运行控制器与前端的测试入口，清理已删除功能的测试；保留微信、BYOK、会话及本地运行管理相关回归。
- 重新生成控制器 OpenAPI 和前端 SDK，检查已删除接口返回 404。
- 构建 shared、dev-utils、slimclaw 库、web、controller 和 desktop。
- 新增测试验证：旧云配置不能进入模型库存；旧 IM 配置不能进入运行配置；只有选择可用自带模型后才可开始扫码；用户不能通过旧设置重新启用统计。

最终结果：类型检查、全仓 lint 与上述各模块构建通过。主测试集 601 项通过、38 项因平台/集成条件跳过；控制器专项 120 项通过，前端专项 22 项通过。专项与主测试集有重复用例，不把它们相加作为独立覆盖数量。前端构建仍提示单个 JS 包超过 500 kB，这不阻止构建，后续可按页面拆包。

没有使用真实 API Key、真实微信账号，没有进行端到端回复测试、长时间运行测试或 Windows 安装包测试。预设编辑、清理记录、密钥加密、独立应用标识和更完整的故障提示仍按 ROADMAP 推进。

## 第二轮：首次配置与运行状态（2026-10-20）

以下为第一轮之后的增量，覆盖上文对应的旧状态：

- 新增简化设置页：默认 DeepSeek，其他兼容接口放进高级设置。后端调用选定模型的 Chat Completions 接口生成短回答；明确提示 API 用量，失败不替换模型。通过后一次保存供应商与默认模型，避免分两次保存产生不一致。
- 新增密钥／权限、额度、限流、接口／模型、超时和网络错误说明；不把服务商响应正文或密钥回显给前端。自定义远程地址要求 HTTPS，本机地址可用 HTTP；不跟随带密钥的请求重定向。
- 删除扫码模拟百分比与无限重试；最多三次获取二维码，等待和同步均有限时，取消后丢弃过期响应。服务端以原二维码创建时间计算有效期，并在取消后拒绝保存迟到的确认结果。
- 首页新增后台实时状态、微信就绪状态、回复阶段与最近成功发送时间。微信插件仅记录阶段、随机运行编号、时间和错误类别，状态文件没有聊天正文、联系人、API Key 或微信令牌。
- 微信发送结果校验业务返回码；HTTP 200 不再自动等同于发送成功。首页明确区分接口接受发送和手机实际收到。
- 暂停状态保存在本机，微信插件在处理新消息前检查。暂停期间忽略新消息；已开始处理的消息可能继续完成。
- 用户预设通过模型插件按 agent 在每次回复时加载，修改和留空清除均有测试。运行状态文件原子替换，避免读取一半内容。
- 新开对话通过运行服务的 `sessions.reset` 完成，保留预设；旧本机记录不删除。界面不调用原来仅截断本地文件的重置方法。
- Windows 产品名为 WeChat AI Bridge，appId 为 `com.wechataibridge.desktop`，配置目录 `~/.wechat-ai-bridge`、桌面数据目录 `%APPDATA%/wechat-ai-bridge`、注册表 `Software\WeChatAIBridge\Desktop`。保留原 MIT 许可，图标与启动素材完整替换仍待完成。
- 打包前置检查改为验证微信／模型插件，不再要求已删除的 QQ 和钉钉依赖。Windows 暂存目录切换加入有限重试。打包前需要停止开发服务，避免文件监视器占用目录。

开发模式的 Electron、Web、Controller、OpenClaw 已实际启动，并检查了首页和 API 设置页。运行中的命令调用探针返回 404 / `not_found`；读取到的运行配置为 `tools.deny=["*"]`、执行策略 deny、cron 关闭、memorySearch 关闭。这是本地工具接口与配置检查，不等同于完整的模型行为安全验收。

验证结果：主测试集 626 通过、38 跳过；控制器原完整专项 121 通过，另补二维码取消与到期用例 2 项通过；前端专项 22 通过。类型检查、微信插件对实际固定版本 SDK 的类型检查、lint 通过。各测试入口存在重复用例，不相加作为独立测试数量。

尚未使用真实付费 API 或微信账号验收。密钥的操作系统凭据保护、所有密钥副本和诊断日志审计、删除本机历史数据、签名安装包及普通用户安装／升级／卸载／长期运行验证仍未完成。新流程不能据此宣称已经可以收费发布。

Windows 本地打包最终通过（`pnpm dist:win:local`，使用已安装的同版本 Electron 37.10.3，未发布）。产物为 `apps/desktop/release/win-unpacked`，整个目录实测 881,275,622 字节，约 840.5 MiB，后续仍需要缩减运行依赖。它是解压运行目录，不是已签名安装器。

停止开发服务后，独立启动其中的 `WeChat AI Bridge.exe`：打包态标识为 true，主界面可见，后台 Web 与 OpenClaw 监听进程均来自该解压目录，启动健康记录无失败。检查完成后通过正常退出接口关闭测试程序及其后台。没有填写实际 API、登录微信或执行真实收发。初始启动使用了本机运行缓存，因此不把这次结果当成干净机器上的首次安装耗时。

## 第三轮：界面与交互打磨（2026-10-20）

- 重做首页、模型设置、回答风格、对话管理、扫码和确认弹窗；统一暖白、深绿配色、Bridge 图形标识与排版。高级供应商页同步标题、导航和品牌。
- 加入模型到微信的 SVG 连接流线、浮动卡片、入场和悬停动画。支持持久化动态效果开关，以及系统的减少动态效果偏好；不增加远程字体或图片请求。
- 保持两步配置与可选试聊。只有模型配置可用、微信已授权且对应服务就绪时，才显示连接就绪；不等待首条回复。
- 扫码面板展开时自动定位并获得焦点；设置页签支持方向键、Home、End；弹窗关闭后焦点回到原按钮。小窗口保留导航名称和帮助入口。
- 多轮浏览器检查覆盖 1440×1000、1024×768、390×844：修正辅助文字过小、窄窗口导航名称缺失、扫码区域不在视野内、错误提示间距和弹窗焦点丢失。
- 使用临时模拟接口验证模型表单、密钥显示切换、预设保存、页签键盘操作、帮助弹窗、二维码取消、暂停恢复、示例消息复制及动画开关。模拟接口和截图位于忽略目录 `.tmp/`，不属于正式运行环境。

本轮使用 Node.js 24.19.0、pnpm 10.26.0。全仓 lint、Web 类型检查和生产构建通过；`pnpm exec vitest run tests/web` 的 14 项测试通过。高级供应商页改为按需加载，主 JS 包仍有超过 500 kB 的构建提示。

本轮没有重新打包 Windows 程序，也没有使用真实 API Key 或微信账号。上述结果用于界面和前端交互验收，不代表真实微信收发或安装包验收完成。

## 第四轮：配色、操作指引与真实扫码入口（2026-10-20）

- 新增松林绿、海盐蓝、鸢尾紫、暖砂色四套全局配色。右上角可即时切换，记住本机选择；原有动画开关和减少动态效果偏好仍保留。
- 首页明确展示环境准备、模型 API、微信授权三个阶段，按真实查询结果提示下一步；读取失败时提供重新检查入口，避免用缓存状态宣称已连接。
- 模型页显式展示服务商选择和操作顺序；兼容接口直接展开地址、模型字段。保存后提供「下一步：连接微信」。扫码页说明手机入口、确认步骤、重新获取和常见无效原因，首次试聊仍可选。
- 修复本地预览遗留问题：第三轮结束后，5173 页面仍代理至模拟接口 5391，模型保存为模拟成功，二维码为 `example.invalid` 占位链接。这使用户无法真实授权，属于交付错误。该模拟进程已停止、脚本已移除；原页面端口现由开发 CLI 启动并连接真实 Controller 50800 和 OpenClaw 18789。此前在模拟页填写的 API Key 未保存到真实后端，需要在真实设置页重新填写。
- 二维码渲染区分图片与授权链接，使用黑白高对比和四模块留白。拦截空内容、无效协议和保留测试域名，异常时停止等待并给出明确错误，不再把占位文字渲染成可扫码图案。

Windows、Node.js 24.19.0、pnpm 10.26.0 下已准备固定版本 OpenClaw 2026.3.7 并启动真实本地服务。Controller 健康检查和运行时连接均通过；通过实际二维码接口获取到 `liteapp.weixin.qq.com` 的 HTTPS 授权链接，未保存该链接或登录会话到文档。首次冷启动 Controller 曾因运行时同步重启触发等待超时，运行时稳定后再次启动成功；冷启动体验仍需单独优化。

验证：Web 类型检查、生产构建、全仓 lint 通过；前端专项 19 项通过，新增占位二维码拒绝、二维码内容分类、步骤指引和服务读取失败回归。浏览器检查覆盖 1440×1000、390×844，验证配色切换、刷新后保留、方向键选择、兼容接口展开及设置页签标题。主 JS 包仍有超过 500 kB 的构建提示。

本轮没有使用真实 API Key，没有在手机上确认微信授权，没有验证实际模型回复，也没有重新打包 Windows 程序。实际获取微信授权链接只证明真实二维码入口可用，不代表完整微信收发验收完成。
