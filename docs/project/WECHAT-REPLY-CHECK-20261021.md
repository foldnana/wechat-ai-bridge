# 微信收发排查（2026-10-21）

## 发现的问题

用户已保存模型并完成微信扫码，但没有收到回复。检查发现：本地服务和模型配置正常、自动回复未暂停；微信通道没有注册成功，运行日志为 `Cannot find module 'zod'`。

微信插件必须携带自己的生产依赖 `zod@4.3.6` 和 `qrcode-terminal@0.12.0`。旧包只有插件入口，开发目录还可能回退到仓库根目录的 Zod 3，复制到用户的 `state/extensions` 后便无法加载。因此，仅检查应用首页或本地服务健康不足以验收微信功能。

补全插件依赖并重启后，真实微信通道恢复为 running/configured/ready。程序随后接收到了用户之前发送的消息，完成了模型回答；用户截图确认手机确实收到了正常回复，同时也收到了一条错误的发送失败提示。

第二个问题是发送回执判断：本地协议声明 `SendMessageResp = {}`，旧判断却强制要求 `ret === 0`，将成功的空对象误报为 `WeChat rejected message (code unknown)`，进而又发送错误通知并把本地活动标记成失败。

## 修复

- `be5281c`：打包前、Controller sidecar 和最终 Windows/macOS 产物都校验插件本地依赖、固定版本、入口可解析和目录可独立复制；禁止依赖父目录或外部符号链接补齐模块。Windows 实际重打包验证，macOS 仅修改脚本，未作平台验收。
- `3808f41`：兼容 HTTP 成功时的合法空 JSON 对象；出现的 ret/errcode 仍必须是数字零。非零、无效类型、无效 JSON、数组或 HTTP 错误仍会失败，不把所有返回都当成功。
- 更新开发文档，说明跳过运行时 postinstall 后必须单独安装微信插件的锁定生产依赖。

## 验证与边界

- 9 项便携插件依赖回归测试、19 项回复控制与发送回执测试通过；RuntimePluginWriter 原有 6 项复制测试通过。
- 实际将插件复制到脱离仓库的目录后，Zod 4.3.6 和二维码依赖均能加载。
- 类型检查和 Biome 检查通过。Windows 解压版重新构建，已有模型配置和微信授权保留。
- 最终版本 `3808f41` 的新消息已完成真实闭环：北京时间 18:43:09 收取、18:43:10 生成、18:43:11 发送成功，活动 error=null；用户明确确认手机只收到正常回答，没有附带错误提示。该结果仅覆盖当前开发机、已有模型和授权的一次正常收发，不代表断网、重连、凭据过期或其他设备已通过验收。
- 排查只记录连接状态与收取/生成/发送时间，不将密钥、微信凭据或聊天正文写入仓库。没有由开发工具主动发送测试消息。
