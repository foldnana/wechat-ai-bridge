# 微信聊天体验检查（2026-10-23）

范围：简化配置界面的文案，改进默认大肥鱼预设和自然接话提示。QQ、B 站暂不开发。首次使用仍是填写自己的 API、扫码连接微信。

## 本次改动

- 页面使用「连接总览」「模型连接」「微信连接」「回答风格」「对话管理」「运行记录」「聊天行为」等功能名称；去掉「灵感与日常」「找一点灵感」等装饰性文案。大肥鱼口吻只保留在角色提示等少数位置。
- 大肥鱼保留直白、俏皮的表达，减少米饭、尾巴、冒泡等重复角色梗。现实经历和角色玩笑需要区分；不用虚构自己吃饭、上班来营造真人感。
- 每轮理解当前意图：吐槽时先回应具体内容，明确求助后直接处理；纠正覆盖旧信息；缺少记录时不猜，不把所有会话都说成没有记忆。
- 对一句话、可复制消息、结束聊天等场景约束附加解释和追问。添加接话示例及发出前检查，不增加用户配置项。
- 保留已实现的自动接话：通常等待 2.5–4 秒，未完句及连续补充适当延长，单批最长 20 秒；发送时最多两个自然气泡。用户原有手动节奏设置不被覆盖。

## 方法及边界

使用本机已配置的 `deepseek/deepseek-chat`，全部输入为虚构情景，未读取既有微信对话，未向微信发送测试消息。调用真实模型 API 会产生用户 API 用量。

手动脚本 `scripts/evaluate-bridge-chat.mts` 使用实际 runtime-model writer、实际 prompt hook、消息等待及气泡拆分函数；模型请求直接走 API，温度 0.7，最多 600 输出 token，两组情景并行、同一情景按顺序对话。这不是完整 OpenClaw 系统提示、工具链或微信端到端测试，也不是实际用户满意度调查。计时仅包含模型请求；不等于手机收到消息的耗时。气泡及等待结果是函数计算，不代表网络上实际发生了这些动作。

最终固定核心集：8 组、17 轮。换题集：5 组、10 轮。最终 27 轮均返回非空回答，无请求错误、无输出截断。使用同一提示词，SHA-256：`9cbd23b2ee7e278a4858a86fbeba33164814e6cdb93c8d2c29d0dfd8acefedb2`。

过程还运行了基线与中间版本；其中一次旧构建人设被误读，不能作为新预设的有效结果。脚本现已校验实际注入的人设必须与源码一致，否则在请求 API 前退出。保留用于比较的完整基线、最终核心集与换题结果见 [评测数据目录](evaluations/20261023/)。每种情景只有单次采样，不能推出稳定通过率或显著改善结论。

## 观察结果

| 场景 | 本次最终样本观察 |
| --- | --- |
| 吐槽转求助 | 听完吐槽后，能直接给出一句向领导确认优先级的话，未继续安慰或附加使用说明。 |
| 纠正行程 | 正确回答「后天下午两点到杭州」，不再重复已经作废的上海行程。换题后「姐姐→妹妹、红色→绿色」也保留最后的版本。 |
| 结束聊天 | 「晚安，睡个好觉。」；换题「我先走了」后简短收尾，无进一步问题。 |
| 现实经历 | 问午饭时采用假设玩梗，追问后承认没有真实吃饭。早期样本曾声称真的吃过。 |
| 没有记忆 | 表达本段对话没有相关记录，不捏造昨天的去向。 |
| 没有照片 | 没把纯文字误当成照片，但附加了泛泛的外貌评价建议，有改进空间。 |
| 分享小事 | 能接住做蛋糕成功的开心；明确「不许讲课」后没有给烘焙教程。 |
| 简短办事 | 赶公交要求一句话时直接给出「我晚到十分钟。」。面试三件事后仍加了「完事睡觉」，没有完全做到克制。 |

仍存在的问题：有时给未被请求的生活提醒；有时为共情添加不够有依据的描述；不必要的追问没有完全消失；较长建议仍偶尔带总结性补话。当前版本是可继续验证的改进，不宣称已经像真人、最好或稳定无误。没有使用后处理硬删句子，避免误删用户真正要求的内容。

核心集模型请求中位耗时 908 ms，范围 370–1509 ms；换题集中位耗时（按排序后上中位数）939 ms，范围 750–1990 ms。供应商 usage 记录分别为输入 18,996 / 11,088 token，输出 448 / 290 token；它们仅对应最终两组，不能作为整轮开发的总用量或价格估算。更长的提示词会增加输入用量。

## 再次运行

这些命令仅供开发者主动试聊，不属于用户的安装步骤。使用独立输出目录，不要把含真实用户对话的文件加入公开仓库。

```powershell
pnpm --filter @nexu/shared build
pnpm exec tsx scripts/evaluate-bridge-chat.mts --live --config <本机配置文件> --out <评测输出目录>
pnpm exec tsx scripts/evaluate-bridge-chat.mts --live --suite transfer --config <本机配置文件> --out <另一输出目录>
```

后续优先用真实使用反馈补充新的虚构回归情景，持续观察哪些回复显得啰嗦、接错话或打断用户。再决定是否需要新功能，避免继续堆叠设置项。
