# 模型列表选择检查（2026-10-23）

## 行为

「模型连接」填写 API Key 并离开输入框时自动读取列表；自定义服务需同时填写接口基础地址。下拉框展示服务商返回的模型 ID，保留当前选择（若仍在列表中），否则选择首项。用户还可刷新列表或切换为手动填写。

读取列表不会生成回答、保存密钥、替换模型或重启运行时。只有「测试并保存模型」仍沿用原来的真实生成测试与保存流程。模型出现在列表中不代表有聊天权限或支持 Chat Completions。

更换服务商清除待提交密钥；更换密钥、地址清除旧列表并取消前端请求。迟到的结果不再更新当前选择。读取较慢时也能直接改用手动填写。接口不支持、列表为空、鉴权失败、限流及读取超时都提供手动填写/重试提示。

## 接口与边界

- 新增本地 `POST /api/v1/bridge/models/discover`，凭据在请求体中传给控制器，不进入 URL 或 React Query 缓存键。
- 控制器只向选定基础地址的 `/models` 发起 GET；复用已有代理和地址验证，拒绝远端明文 HTTP、URL 内嵌凭据、查询参数等。拒绝跳转，不跟随服务商提供的任意 next URL。
- 支持 `data[].id` 列表及 `has_more` / `last_id` / `after` 形式的分页。最多 10 页、5,000 个 ID、每页 2 MB、整体 20 秒；重复游标或达到上限时明确标记可能不完整。其他分页协议不作兼容承诺。
- 去重、排序，跳过空值、过长 ID 及控制字符。未接入的供应商、未授权模型和不提供列表的接口不能凭空列出，可手动填写。
- 仅调用列表接口的真实验证不等于新模型已完成聊天验证。
