# 开发计划与验收标准

状态：项目已初始化，功能改造尚未开始。

## 目标用户和交付

面向不懂服务器、命令行和运行环境的 Windows 用户。用户自行购买 API，工具在本机连接微信。收费对象是软件或安装协助，不销售模型额度、不托管用户机器人。

成功标准：用户可以独立完成安装、配置 API、微信授权，并收到第一条回复；日常故障可以通过明确的提示恢复。

## 第一版范围

四个页面：

1. 首次配置：选择模型 → 填 API → 真实模型测试 → 微信扫码 → 首条回复验收。
2. 运行首页：运行状态、最近成功回复时间、启动/暂停、重新连接、诊断。
3. AI 设置：模型和密钥、用户预设、新开对话、数据管理。
4. 软件设置：开机启动、窗口关闭行为、更新、故障报告、开源许可。

排除：云端托管、模型转售、nexu 账号/积分/奖励、其他 IM 渠道、技能市场、办公自动化、小程序、普通微信群支持承诺。

头像修改不作为第一版承诺，须先核实微信通道是否允许程序化修改。新开对话、清除长期记忆、删除本机记录是不同操作；不宣称可以删除微信服务器或模型服务商保留的数据。

## M1：最短首次配置路径

- [ ] 默认自带 API，不要求注册 nexu 账号。
- [ ] 默认 DeepSeek；其他兼容接口收纳到高级设置。
- [ ] 测试选定模型的真实生成能力，不只请求模型列表。
- [ ] 微信连接使用真实阶段提示，限制持续重试并提供重新启动。
- [ ] 连接成功后，引导用户发测试消息；确认收消息、生成、发送三段结果。
- [ ] 已保存步骤可继续；退出后不丢失已完成配置。
- [ ] 区分密钥错误、模型不可用、限流、余额/额度、网络、授权过期与运行时启动失败。

验收：干净 Windows 机器上，不用命令行完成配置；遇到可恢复错误有可操作提示。真实 API 测试会产生用量，应在界面说明。

## M2：交付前权限与数据改造

- [ ] 在运行时禁用系统命令、任意文件操作、浏览器控制、自动任务和技能安装。
- [ ] 去除上游账号、积分、奖励、云模型及对应后台依赖。
- [ ] 关闭继承的聊天内容跟踪；审计统计、崩溃报告和外部请求。
- [ ] 密钥采用操作系统凭据保护；审计主配置、备份和运行时中的全部副本。
- [ ] 诊断默认不含密钥、微信凭据和聊天正文；用户主动导出。
- [ ] 使用独立 appId、数据目录、品牌和帮助地址。
- [ ] 替换/停用上游更新源，不能让改版自动覆盖为 nexu 原版。

## M3：用户配置与生命周期

- [ ] 用户预设的保存、生效、恢复行为明确。
- [ ] 新开对话保留预设，不继续携带旧上下文。
- [ ] 第一版默认关闭自动长期记忆；如保留，提供可验证的数据清理机制。
- [ ] 开机自启为可选项，关闭窗口与完全退出有明确区别。
- [ ] 断网恢复、授权过期、休眠唤醒后能恢复或提示处理。
- [ ] 重新安装与升级保留配置，更新失败可恢复。
- [ ] 卸载明确区分保留数据与删除本机数据。

## M4：发布门槛

- [ ] 实测 Windows 10/11 目标版本、中文用户名和普通用户权限。
- [ ] 首次安装、重复启动、端口冲突、断网、休眠、重启均有结果记录。
- [ ] 更换 API/模型后，下一次回复确实使用新配置。
- [ ] 长时间运行与连续消息测试无明显重复回复、丢回复或后台残留。
- [ ] 核对最终安装包所有依赖和素材许可。
- [ ] 安装包签名、更新来源、完整性验证和升级回退方案明确。
- [ ] 文档说明电脑必须保持运行、API 费用自付、微信展示形式及兼容版本。
- [ ] 由至少三位非技术试用者独立操作，记录卡点和人工支持时间。

## 已知核查依据

上游基线中观察到：微信连接视图使用模拟进度和持续重试；模型验证主要读取模型列表；运行配置允许命令执行；API 可写入 JSON 配置；带条件启用的统计/内容跟踪；保留 nexu 更新地址。

这些是静态代码检查结果，不代表已在安装包中复现故障。每项改造须在实现和运行测试后才能标记完成。
