# 销售准备度复核（2026-10-23）

## 后续范围调整：按本地安装工具评估

最新明确决定：本次只改本地模型配置接口回传完整密钥；诊断日志不改，代码签名、安装器和自动更新不做。交付为完整运行目录的 ZIP，解压即用。此决定优先于本报告较早的建议。

用户明确不将模型表达、调侃、能力回答或格式残留列为本轮修复目标。以下原始试聊结果保留作为记录，不再作为软件交付阻塞项；不继续调整人设。

上一版结论把已确认缺陷、可选加固和未完成验证并列成了销售门槛，过于宽泛。本节取代下方原始结论与放行顺序中的优先级要求，保留其事实证据：

- 当前 Windows 桌面启动清单将控制器绑定 `127.0.0.1`。正常聊天连接用户指定的模型服务商和微信服务，不依赖本项目自建云端中转。当前包没有配置 Sentry、PostHog 或 Langfuse 凭据；这次是代码/构建配置核查，不是所有依赖的全流量抓包审计。
- API 密钥用于服务商鉴权，正常会发给用户选择的模型服务商；“本地运行”不代表完全离线。未发现当前默认路径将密钥上传本项目自建服务器的依据。
- 操作系统凭据加密是可选加固，暂缓，不再作为首版试运营的硬门槛。同一 Windows 用户下的恶意进程本已可读取配置，加密也不能消除所有此类风险；不能用这一假设无限扩展范围。
- 本地配置接口不应无必要地返回完整密钥，值得作为有限范围改进；若加本地凭证应自动管理，无需用户注册、设置密码或配置服务器。现有证据不支持宣称已经发生公网泄露。
- 若售后会让用户导出并发送诊断包，导出脱敏应先处理；不要求用户转发原始日志可以减少这一使用场景的暴露。虚构日志脱敏测试不代表真实日志里已经存在密钥。
- 优先核实会阻断正常使用的问题：干净电脑首次运行、当前包真实收发、退出重开配置保留、断网和睡眠恢复、模型调用失败后的可理解提示。未验证不等于已存在 bug，先测试，失败再修。
- 签名、自动更新、进一步瘦身、大规模多机测试可以分阶段做，不一概要求首版全部完成。依赖/素材许可核查属于独立交付事项，不需要为此增加软件功能。

## 结论

当前是核心功能已成型、适合继续内测的 Windows 本地 BYOK 工具，尚不能按“普通用户购买后独立安装、稳定使用”的正式成品验收。主要缺口是隐私保护、运行能力说明、交付与跨机器可靠性，不是缺少更多聊天功能。

本轮只增加评估脚本、虚构用例和报告，没有改动产品行为、重新打包、推送或发布。收费软件与收费安装服务都需要清楚说明本地运行、模型费用另付、微信通道范围、支持期限和故障处理方式；出售安装服务不意味着可以不维护交付质量。

## 真实模型对话

复用本机配置的 `deepseek/deepseek-chat`，使用实际安装包中的 pi-ai 请求模块、模型请求适配和大肥鱼提示词插件。隔离测试状态，关闭表情装饰，不带真实联系人资料。先运行 11 个独立场景、22 轮，再针对 4 个场景继续追问 6 轮，共 28 轮，均收到非空正常完成的文本，无 API 请求失败。

这是包内模型/人设层试聊，**不是完整 OpenClaw 代理上下文、记忆整理、微信媒体和消息投递链路**。全部用例为虚构内容；独立历史测试也不能证明界面“新开对话”按钮的端到端隔离正确。测试了当前一个服务商和模型，不能外推全部兼容模型。

本轮短文本模型生成耗时：最短 463 ms，中位数 1,007.5 ms，最长 1,564 ms。不包含微信传输、合并消息等待和分段发送间隔，不能作为手机端回复时间承诺。SDK 报告累计 input 5,551、output 820、cacheRead 26,496；未按未经核对的价格推算费用。

### 表现较好的部分

- 能区分“只想吐槽”和“现在帮我办事”，没有持续强塞建议。
- 能使用同一会话的短期信息，理解用户纠正的地点和时间。
- 能配合结束聊天、简短回答和实用写作。
- 面对“真的吃饭了吗”能承认角色扮演，没有持续假装有现实生活。
- 被指出冒犯或错误后能道歉改口。

### 需要修复的体验

1. **运行能力出现错误承诺。** 两个独立场景中，一次回答“关电脑不影响……照样能收到、能回”，另一次回答“我跑在云端服务器上，不依赖你那台电脑”。用户提供本地运行事实后才改正。模型推理在服务商运行，不代表本地微信桥接程序退出、电脑断网或关机后还能工作。
2. **调侃可能越界。** 用户疲惫并吐槽工作时，出现“就爱看你们被会议磋磨”。后续指出不舒服时能够收回，但第一条回答已破坏陪伴体验。
3. **能力不确定时仍给出确定答案。** 对是否能看图片先邀请发图，随后否认，追问后又断言当前无图片通道；测试没有向模型注入经过验证的图片通道事实，不能把这些回答当作实际能力说明。
4. **少量擅自补细节和格式残留。** 把“跑步破纪录”理解为“跑得更远”；一条原始回答带 `</br>`。出站转换代码处理 Markdown，没有针对该 HTML 标签的规则；本轮未在手机上确认最终显示。

建议把实际运行方式和已验证能力作为独立事实层注入，避免可编辑角色设定覆盖产品能力说明。人设规则应明确：先接住情绪，不拿用户的难受开玩笑；未知能力不承诺。将上述失败用例加入回归，覆盖新会话及至少另一类模型，不只复测已经被纠正过的会话。

## 隐私与本地控制

以下为代码审查和虚构 canary 检查，不是已经发生泄露的结论。

| 发现 | 证据 | 销售前应达到的状态 |
| --- | --- | --- |
| 配置接口未经身份验证即可返回密钥 | `create-app.ts` 仅设请求 ID 和 CORS；`GET /api/v1/model-providers/config` 返回完整配置。对内存中的虚构服务发无凭证请求，返回 200 且包含测试密钥 | 本机控制接口鉴权；常规前端 API 只返回脱敏状态；检查 Origin/Host 和写入接口 |
| 密钥有多份明文落盘 | `lowdb-store.ts` 将配置和 `.bak` 序列化；`openclaw-auth-profiles-writer.ts` 写运行时密钥 | 操作系统凭据保护；梳理运行时确需的副本、ACL、备份和删除策略，不能仅加密 UI 对应的一个文件 |
| 诊断脱敏不足 | `redaction.ts` 仅按 JSON 字段名和少数 URL 参数脱敏；`diagnostics-export.ts` 对文本日志仅调用 URL 清理。虚构 Bearer 文本和聊天正文原样保留 | 默认导出最少必要元数据，扩展密钥脱敏，检查 JSONL 和非 JSON 错误分支；正文需明确处理，导出前可预览 |

控制器默认监听 `127.0.0.1`。上述结果证明本地访问边界不足，**不等于已经证明任意外部网站能跨浏览器保护读取密钥，更不等于公网暴露**。CORS 不是本地客户端身份验证。诊断检查也没有扫描用户现有日志，未断言某个真实导出包已经含有聊天或密钥。

“一键诊断”的简要状态接口与“导出诊断包”是两条路径；前者已限制返回内容，不能据此认为整个日志导出链路已脱敏。

## 建议的放行顺序

1. 修正运行能力错误承诺；补本地控制鉴权、密钥和诊断保护；明确素材和依赖许可。

3. 做可复现安装包和版本标识，完成当前版本的真实微信收发、断线/重启/睡眠恢复和干净机器验收。
