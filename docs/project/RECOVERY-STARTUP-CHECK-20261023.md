# 故障恢复、启动计时与点击修复（2026-10-23）

## 本次变更

- Windows 桌面壳不再叠加透明拖动区域。原区域高 38 像素、覆盖在 WebView 上方，截住顶部按钮中部的鼠标事件；Windows 已有原生标题栏，不需要这层覆盖。两个桌面壳实现同步修正。
- 顶部新增「诊断」，总览故障状态提供「诊断并重试」。检查本地服务、是否保存模型、微信通道状态；模型配置存在不代表余额或生成可用，通道就绪也不宣称完成真实收发。
- 诊断走桌面 IPC，因此控制器停止后，已经打开的页面仍能启动恢复。用户点击「重试启动服务」后再次检查，恢复异常控制器及其依赖。正常后台不会因缺少 API 或微信授权而重启；并发点击合并为一次操作，失败后可再次重试。重试保留本地配置与授权，但可能中断当前回复。
- 诊断结果只提供状态与耗时，不返回 API Key、日志正文或聊天内容；不调用生成接口、不发送微信消息。
- 启动阶段以进程启动为起点记录单调时钟耗时。区分主窗口、配置服务、操作页面和完整聊天后台；后台检测异步进行，不阻塞首屏。首次完整就绪观察最多持续 120 秒，未记录的阶段明确显示「尚未记录」。各阶段并行，时间不可相加。
- Windows 打包剔除运行时目录内的 JS/TS/CSS source map 与 PDB 调试符号，保留运行代码、TypeScript 源文件、native 模块、图片和许可证。需要调试包时可设置 `NEXU_KEEP_DEBUG_SIDECARS=1`。
- 打包模式遵守显式 `NEXU_HOME` 覆盖，供隔离验收使用；普通用户未设置时仍使用原有目录。

## 测试过程中的报错

首次尝试旧包隔离测试时，测试脚本覆盖 Windows 用户目录变量，Electron 在取得 `appData` 时抛错并弹窗。该实例启动失败后已结束，未进入微信收发流程。脚本现保留系统目录，只指定软件配置目录和 userData；新包已实际启动、测试恢复并正常退出。测试脚本曾在退出后访问已销毁的 Playwright 对象，属于清理脚本错误，现保存子进程引用后再退出，最终完整运行返回成功。
